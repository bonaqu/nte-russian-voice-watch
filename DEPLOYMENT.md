# Пошаговая публикация на GitHub Pages

Инструкция рассчитана на аккаунт `bonaqu` и репозиторий `nte-russian-voice-watch`.

## 1. Распаковать архив

После распаковки внутри должны сразу находиться:

```text
.github/
assets/
data/
scripts/
tests/
index.html
appeal.html
manifest.webmanifest
README.md
...
```

Важно: в репозиторий нужно загрузить эти элементы в корень. Не должно получиться лишнего уровня вида `nte-russian-voice-watch/nte-russian-voice-watch/index.html`.

## 2. Создать репозиторий

1. Открыть GitHub под аккаунтом `bonaqu`.
2. Нажать `+` в правом верхнем углу → `New repository`.
3. В поле имени написать `nte-russian-voice-watch`.
4. Выбрать `Public`.
5. Не добавлять README, `.gitignore` и лицензию: они уже есть в архиве.
6. Нажать `Create repository`.

Публичный репозиторий нужен для бесплатного GitHub Pages на GitHub Free.

## 3. Загрузить файлы без командной строки

1. На пустой странице репозитория нажать `uploading an existing file`.
2. Выделить всё содержимое распакованной папки и перетащить в окно GitHub.
3. Дождаться загрузки.
4. Внизу оставить сообщение коммита, например `Initial release`.
5. Нажать `Commit changes`.

Если браузер не принимает скрытую папку `.github`, удобнее использовать GitHub Desktop или команды из следующего раздела. Папка `.github` обязательна: без неё не будет автоматики.

## 4. Альтернатива: загрузка через Git

Открыть PowerShell в распакованной папке:

```powershell
git init
git branch -M main
git add .
git commit -m "Initial release"
git remote add origin https://github.com/bonaqu/nte-russian-voice-watch.git
git push -u origin main
```

GitHub запросит авторизацию. Пароль аккаунта для Git по HTTPS не используется; подойдёт вход через Git Credential Manager или personal access token.

## 5. Включить GitHub Pages

1. В репозитории открыть `Settings`.
2. Слева открыть `Pages`.
3. В блоке `Build and deployment` найти `Source`.
4. Выбрать `GitHub Actions`.

В проекте уже находится `.github/workflows/pages.yml`, поэтому создавать предложенный GitHub шаблон не нужно.

## 6. Разрешить Actions

1. Открыть вкладку `Actions`.
2. При появлении предупреждения нажать `I understand my workflows, go ahead and enable them`.
3. Дождаться workflow `Deploy GitHub Pages`.

После успешного запуска появится зелёная отметка. Первый адрес:

```text
https://bonaqu.github.io/nte-russian-voice-watch/
```

## 7. Запустить первую живую проверку

Первоначальные JSON содержат проверенную базовую информацию, но после публикации нужно выполнить актуальный запуск:

1. Открыть `Actions`.
2. Слева выбрать `Monitor NTE Russian Voice`.
3. Нажать `Run workflow`.
4. Выбрать ветку `main`.
5. Ещё раз нажать зелёную кнопку `Run workflow`.
6. Открыть появившийся запуск и убедиться, что шаги зелёные.

Workflow:

- устанавливает зависимости;
- запускает тесты;
- проверяет источники;
- обновляет `data/status.json`, `data/evidence.json`, `data/history.json`;
- сохраняет коммит истории;
- публикует свежий сайт.

## 8. Расписание

Проверки запускаются в:

```text
01:17 UTC
07:17 UTC
13:17 UTC
19:17 UTC
```

Это четыре раза в сутки. Минуты специально смещены от начала часа, когда нагрузка GitHub Actions выше.

Запуск по расписанию не является секундно точным: GitHub может поставить задачу в очередь. На сайте всегда отображается фактическое время последней успешной проверки.

## 9. Проверить PWA

На Android в Chrome:

1. Открыть сайт.
2. Нажать меню браузера.
3. Выбрать `Установить приложение` или `Добавить на главный экран`.

На компьютере Chrome/Edge покажет значок установки в адресной строке либо кнопку `+` в шапке сайта.

После первого открытия основные страницы и последние JSON-данные доступны офлайн. При появлении сети данные обновляются по стратегии network-first.

## 10. Проверить карточку Telegram

Отправить ссылку сайта в личный чат или группу. Telegram должен показать изображение `assets/og/og-card.png`.

Telegram может кэшировать старую карточку. После изменения изображения иногда требуется время либо повторная публикация URL с новым query-параметром для теста.

## 11. Настроить бесплатные Telegram-уведомления

### Создать бота

1. Открыть `@BotFather`.
2. Выполнить `/newbot`.
3. Сохранить токен.

### Узнать Chat ID

1. Написать боту любое сообщение.
2. Открыть в браузере:

```text
https://api.telegram.org/botВАШ_ТОКЕН/getUpdates
```

3. Найти `chat.id`.

Для канала добавить бота администратором и использовать ID канала.

### Добавить Secrets

В GitHub открыть:

`Settings → Secrets and variables → Actions → New repository secret`

Создать:

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
```

Никакие токены нельзя записывать в файлы репозитория.

## 12. Что делать при красном workflow

### Упал тест

Открыть шаг `Run detector tests`. Не отключать тест ради зелёной галочки: он защищает от ложного объявления озвучки.

### Источник вернул 403 или изменил HTML

Сайт продолжит показывать ошибки источников отдельно. Создать issue через шаблон `False positive or missed announcement` и приложить оригинальную ссылку.

### Pages не публикуется

Проверить:

- `Settings → Pages → Source: GitHub Actions`;
- репозиторий публичный;
- ветка называется `main`;
- в репозитории есть `.github/workflows/pages.yml`;
- workflow имеет разрешения `pages: write` и `id-token: write` — они уже прописаны.

### Расписание перестало запускаться

Проверить вкладку Actions и меню workflow. GitHub может отключать scheduled workflow в публичном репозитории после 60 дней без активности. Этот проект обычно сам создаёт коммиты истории несколько раз в день, поэтому условие не должно наступать, пока монитор работает.

## 13. Как изменить частоту

Открыть `.github/workflows/monitor.yml` и изменить cron:

```yaml
- cron: "17 1,7,13,19 * * *"
```

Примеры:

```yaml
# Дважды в сутки
- cron: "17 6,18 * * *"

# Один раз в сутки
- cron: "17 9 * * *"
```

Время cron по умолчанию указано в UTC.

## 14. Как добавить источник

Открыть `data/sources.json` и добавить объект. Для официальной новостной ленты:

```json
{
  "id": "unique-source-id",
  "title": "Readable source name",
  "url": "https://official.example/",
  "kind": "general",
  "category": "official_hub",
  "language": "en",
  "authority": 1,
  "discover_articles": true,
  "max_discovered_links": 12,
  "refresh_recent_links": 3,
  "max_article_fetches_per_run": 8
}
```

Новый магазин с отдельной структурой HTML потребует отдельного парсера и тестов. Не добавлять автоматическое подтверждение по непроверенному фанатскому источнику.

## 15. Как обновить презентацию

Текст находится в `appeal.html`, стили — в `assets/css/appeal.css`. Русская и английская версии размещены в отдельных блоках:

```html
<div data-lang-panel="ru">...</div>
<div data-lang-panel="en" hidden>...</div>
```

После изменения фактических цифр обязательно обновить дату, источник и формулировку ограничения данных.
